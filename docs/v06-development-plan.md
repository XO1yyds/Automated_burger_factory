# V0.6 十天工厂经营与成长策划案

日期：2026-10-19。状态：用户已确认按本稿开发，V0.6功能已实现；开发自检与人工验收状态见 `v06-development-status.md`。

基线：V0.5用户已验收，GitHub提交 `1190330047d6cdf02dc58606cc21eaa3b7f07a5b`。本稿保留V0.6设计要求与初始推荐数值；实现证据另记，不将自动检查等同人工验收或平衡验证。后续确认优先于本稿。

## 1. 用户目标与体验主线

用户提出：完整进入游戏流程、十天关卡体验、车间面积四倍、货币与建筑费用、车间三种唯一供货点可收回重放、开始画面、本地存档。核心体验是用多台单功能机器组成工厂，产出提升后承接更大需求。

### 第1项简短开发描述（供用户核对）

设计一轮十天经营：第1天手工制作，第2～3天手搬原料驱动自动设备，第4～5天搭传送带产线，第6天建立并检查电缆网络，第7天首次批量下单，第8天连接交付，第9～10天扩建并优化工厂。每天营业前可以不限时准备；营业时间、订单件数和并发量逐步上升，每天只引入一个主要学习目标。

### 第7项简短开发描述（供用户核对）

成长围绕“补上一个环节，就少搬一次；多接一组设备，就多产一批”。通过同一款汉堡从手工到完整工厂的对照，让玩家看见吞吐、堵塞与交付效率的变化。基础需求随天数递增；上一天产出明显超出基线时，次日提供自愿接受的加量单，不在营业中突然抬高必达目标。

### 推荐保留与边界

- V0.4角色动画继续暂停，本轮沿用白盒表现，不新增菜谱、敌人、员工雇佣、设备等级或在线功能。
- 保留3秒煎肉、自动烹饪3个独立槽、2秒自动组合、0.5格/秒传送带和每网络2件/秒电缆。先调整关卡、布局与需求，不靠暗中加速机器制造成长。
- 车间是逐日搭建并跨日保留的同一家工厂；不每日清空重建，不预先摆好V0.5示例整线。
- 顾客订单、生产任务继续分开：终端下单不自动生成顾客订单，交付组件不自动点击收银交单。
- “自动下单”首版推荐解释为玩家在终端发起批量任务、网络自动索料和生产，沿用V0.5；不新增顾客订单自动转生产任务、库存阈值补货或无人值守重复下单。
- 当前平台：Windows本地开发预览；UI兼顾手机横屏，目标小米14/安卓15，真机结果另验。

## 2. 完整游戏流程

启动 → 开始画面 → 新游戏/继续游戏 → 当日准备 → 主动开始营业 → 制作/搭建/下单/交单 → 营业到时 → 收银确认结束或暂停菜单结束 → 当日结算 → 保存 → 次日准备；第10天结束进入十天总结。

| 状态 | 推荐规则 |
| --- | --- |
| 开始画面 | 不创建运行中的营业循环，不走计时、生产、顾客订单或离线收益 |
| 新游戏 | 无存档时直接建档；已有存档时明确告知覆盖，确认后才开始。教学从第1天开始 |
| 当日准备 | 展示本日目标、新解锁和订单基线；允许已解锁的购买、布置、回收、取放与查阅；所有加工、物流、任务和订单计时冻结，不能用无限准备时间囤无限成品 |
| 开始营业 | 玩家明确点击；生成当日日初回溯快照，再启动生产、物流、订单与营业计时 |
| 营业中 | 正常建造、终端、收银页面继续计时和生产；完整暂停菜单冻结。首次教学说明遮罩冻结，重复打开说明不额外冻结 |
| 时间归零 | 停止新顾客订单，清除未完成顾客订单；保留世界物品、机器、网络和生产任务。沿用V0.5的零时整理阶段：可继续运行与整理，但不再交顾客单、挣钱或计入营业效率 |
| 结束当天 | 收银仅在时间归零后可用；暂停菜单允许提前结束并进入结算。提前结束不视为退出应用或退回标题 |
| 当日结算 | 展示实际交付件数、完成订单数、收入、购置支出、目标结果与产线数据；冻结模拟 |
| 未达标 | 不扣钱、不破产、不删工厂。可继续下一天（无达标奖），或重试当日，完整恢复日初快照，避免刷钱/重复领物 |
| 次日 | 保留建筑、持有建筑、材料、产线、钱和未完成生产任务；新顾客单从零开始。技术按天解锁，不因前一天低分永久卡死 |
| 十天总结 | 展示增长曲线和工厂结果；可回标题或重试第10天。首版不加第11天无限模式；查看工厂为冻结只读，不额外赚钱 |

主目标是教学与日营业件数，不设置不可逆失败。手工线和原料一直可用；购买不足时可先手工交单挣钱。回溯重试替换当日结果，不叠加历史收益。

### 发布与教学规则

- 表中总需求为不含可选加量单的计划上限，不强制把未能发布的订单塞进最后一秒。活跃单满时暂停发布倒计时，腾位后继续等待，不瞬间补发积压订单。
- 第1～3天最后45秒、第4～10天最后60秒不发布新订单；时间归零清除尚未完成订单。没有每单独立耐心倒计时，不做超时罚款。
- 允许部分交付，收银仍须玩家选择订单并确认。界面分别显示“交付件数”“完成单数”“当前n/上限”，不再写死5单。
- 每日达标按实际交付汉堡件数；生产但未交顾客的不算日目标。订单收入按实际交付发放，未完成订单的已交付部分不会在日末追回。
- 每个教学目标首次完成记录一次，不能通过重复拾取/回库刷成就或奖励；按物品身份与事件判断，不用建筑是否存在代替“已使用”。
- 第6天在电缆编辑中提供网络摘要查询，尚未解锁下单时不新增虚构的主动电缆运输；第7天再开放下单组件与任务。
- 第8天必须使用两个不同宿主：下单终端只能依附库存，交付组件依附另一库存或缓存；两组件仍互斥。下单到货先进入本机库存，之后再出库送交付点。
- 每天明确展示一条主教学目标；从第4天起增加一条可跳过的优化目标。教学没有完成只提示复习入口，不强迫玩家在下一天重走长说明。

首轮营业合计2700秒，即45分钟；首次包含教学与不限时布置的目标时长约60～75分钟，须通过实际游玩校准。既有加工理论上限不能当作真实工厂产能，必须计入搬运、带长、回堵、单槽输出和任务交接。

## 4. 效率成长与需求响应

### 可见反馈

- 日常HUD只显示“本日交付/目标、货币、时间、活跃单数”；吞吐和堵塞细节放在统计页，不新增常驻调试信息栏。
- 统计：营业内新产出汉堡、实际交付、自动产出占比、单位营业分钟产量、关键设备空闲/加工/等料/堵塞时间。生产事件去重，搬动物品或重复入库不计新产出。
- 第1、5、10天结算对照，突出相同操作时间内从手工到产线的变化。产线收益先体现为减少搬运、提高稳定性，再体现为批量接单。

### 可选加量订单

- 第3天起可用；第1天无历史，默认不出现。按上一天“营业内新产出/实际营业分钟”对比上一天基础计划需求/计划分钟，并同时要求上一天达到交付目标。
- 产出率达到基线的1.25倍时，次日准备页显示“可选加量：最多增加本日基础件数的25%”。件数向下取整，至少1件，玩家主动勾选才生效；不默认选中。
- 本日基础表、达标件数、已接订单不因此改变。加量单按本日最大单量拆分，遵守活跃上限和末段停单窗口，不承诺一定发布完；同样按件收入，无额外罚款。
- 不在营业中因短时突发产出动态抬价/增单，不按原料无限领取量估产能；日初决定的档位保存进存档。
- 暂停、准备、结算与零时整理不计有效营业时长；不足60秒的提前结束日不触发效率加量，避免极短时长样本失真。

## 5. 车间扩大与初始配置（推荐默认）

- 四倍指可用地面面积：现有18×14=252格²，改为36×28=1008格²，长宽各翻倍。汉堡店仍18×14；格子1米、人物、建筑和物品比例不变。
- 推荐保持车间中心世界X=-40；局部X范围[-18,18]、Z范围[-14,14]。店铺与车间仍独立切换，不能用世界距离远近判断所在区，边界按各房间实际尺寸校验。
- 门口附近保留约12×10格的紧凑起步区，供货点、机器初放与玩家返回点靠近，避免扩大后早期变成远距离跑腿；其余空间开放给长线、分流与并联，不加功能性隔墙。
- 普通镜头沿用V0.5比例和俯视方式，允许原有平移缩放；建造模式有“一览车间/回到玩家”入口，不把整张大地图强制缩到不可读。
- 新游戏第1天车间入口锁定并显示第2天开放。第2天解锁入口并获得车间三种供货点各1个，默认紧凑摆放；自动设备、传送带、缓存、库存、电缆和组件均不预先摆放。
- 解锁是可购买/使用资格，不自动赠送整条产线。后续天数不重新生成供货点，不覆盖玩家布局。

## 6. 货币、购置与建筑库存（推荐默认）

### 金钱与收入

- 单一货币“金币”，非负整数；新游戏50金币，无原料采购费、电费、租金、债务或日末保底扣款。
- 每实际交付1个汉堡收入10金币；完整完成1张订单额外5金币；每日首次达标奖励20金币。单号、交付事件与日奖励有稳定ID，读档不能重复领。
- 部分交付即到账，不等整单完成；取消/过期不退已经支付的真实交付收入。加量单同价，不加第二套倍率系统。
- 每个档案只领取一次新游戏资金；“重新开始/重试”不额外叠加启动资金。日初重试恢复日初余额、收入与奖励标记。

示例预算验证忽略整单额外奖金和加量单，仅计最低达标件数收入与每日达标奖，按紧凑布局依次预留购置支出0/60/60/32/40/100/100/88/72/0金币，日初余额均能覆盖。第4～6、8～9天的带格/线边数是示例预算，不能代替实际路径计价与摆放验证。首版不追求破产压力；后期资金富余可以用于尝试扩建，最终价格须在十天实玩后校准。

### 放置、回收和花费一致性

- 建造页统一显示价格、已解锁、持有数与不足原因；确认前展示本次消耗、余额和预计使用的已有件数。
- 确认合法放置时优先使用“建筑库存”的已有件；不足部分才扣金币购买并放置。未确认、非法、重叠、取消不扣钱；重复事件不能重复购置。
- “建筑库存”是建造菜单内的持有建筑/带格/电缆段记录，不是普通物品库存建筑，不占玩家单件手持位，也不允许把建筑放进材料槽。
- 拆除改为回收建筑至建筑库存，不返金币；移动与旋转不额外收费。重新放置已有建筑免费。首版不加出售菜单，避免引入折旧、退款与无限回购收益。
- 传送带和电缆回收按实际删除的唯一格/边返还件数；共享线路只返实际删除部分。改线时显示新旧差额，先复用旧件，再用持有件和金币补足，取消整次不变。
- 组件卸下只回收组件，不回收宿主；拆宿主同时回收其组件。加工中、任务预约和断线确认仍遵循V0.5限制。
- 容器内容不是建筑价格的一部分。回收前展示物品处理结果；沿用已有落地规则，对无法落地而会删除的品类/数量明确确认，不能无提示损失。教学引导先清空再回收。

## 7. 三种供货点的唯一性与回收（推荐默认）

- 范围仅为车间：生牛肉、汉堡胚、生菜各1个；店内手工供货点保留原样，不把两区误算成同一种可重复购置资产。
- 三个供货点保持无限供料性质，不因收回获得无限原料存量。收回保存的是供货建筑本身。
- 各自固定资产ID与品类；“场景已放置数＋建筑库存持有数=1”，预览状态不创建第二份实体。不得购买、复制、卖掉或真正删除。
- 管理→选供货点→回收→建筑库存显示该品类×1→选择→预览/旋转→明确确认放置；成功后持有数变0。取消预览仍持有1。
- 仅允许在车间合法网格摆放，遵守建筑、传送带、物品与入口占位规则。原供货点尺寸先沿用2×1.5，不因四倍车间放大模型。
- 关联传送带/电缆时沿既有管理规则先处理连接；回收不把带中物品复制回源头，也不凭空终止生产任务。拆线后任务保留并等待，玩家可取消。
- 每次回收/确认放置与存档事务绑定；读档校验唯一资产守恒。异常档案不自动补第二个；优先回退备份并解释。

- 有合法存档才启用继续，并显示第几天、准备/营业/结算、上次保存时间；没有存档时突出新游戏。
- 设置沿用V0.3规范；不先制作正式封面图或付费素材。所有主按钮满足现有手机热区与安全区标准。
- 暂停菜单分开保留“继续 / 保存并返回标题 / 结束当天 / 设置”；返回标题不等于提前结算，不复用一个含糊“退出”按钮。

### 保存方式与覆盖范围

- 一个本地经营档案、一个上一版备份；额外维护当前日初回溯快照供重试，不做多档位、云同步或离线生产。
- 按官方 `engine-docs/recipes/file-storage.md` 使用相对文件名，由Maker自动隔离至当前项目和当前用户的保存区。Windows/Android均走原生File API，不调用已屏蔽的路径getter，不硬编码开发机路径；Web/WASM本地文件不承诺刷新持久化。
- 自动保存：新游戏创建、进次日、结算、第10天总结、营业每30秒；购置/回收/绑定、交单入账后合并保存一次；Android切后台及“保存并返回标题”立即保存。
- 保存冻结逻辑到帧末一致状态后序列化，不让文件IO期间漏生产或重复收银；仅记录数据，不保存引擎节点、UI控件或Lua闭包。
- 内容：版本/schema、档案ID/随机状态、天数/状态/剩余时间、金币与收支/奖励去重、已解锁与教学、建筑持有数和唯一供货点、世界建筑/组件/稳定ID、玩家位置朝向/区域/手持、地面物品、存储栈与身份、机器材料/槽进度/成品、传送带货物与进度、电缆图、生产任务/队列/预约/入库去重身份、顾客订单及发布计时、每日统计与历史、当前加量选择、日初回溯引用。
- 引入持久物品ID和任务ID，不能直接序列化以Lua表地址为键的入库去重标记或锁；恢复时从数据重建引用与预约，避免刷到货/复制/丢物。
- 不保存悬停、拖拽中预览或弹窗焦点。保存未确认的编辑时只保存此前已提交世界；读档回正常操作状态并暂停，玩家点击“继续营业”才运行。准备/结算读档回各自状态。
- 无离线收益：系统时间仅用于“保存于”显示，不拿关机时长推进机器、订单或日计时。
- 实现采用两份交替写入的带序号/校验码存档：仅写旧槽或空槽，写后回读校验，始终保留最新有效槽；加载选择序号最高的有效数据。避免依赖沙箱内未验证的覆盖重命名语义。两份均坏时先保留损坏内容副本再新建；保留失败拒绝覆盖，不静默丢弃。
- Windows开发预览兼容：已实测Maker 0.0.36 manifest预览把`savedata/0`置于每轮TEMP缓存，刷新会清理。`launch-demo.ps1`启动隐藏的`preview-save-bridge.ps1`，仅核对本项目会话与Runtime后备份两个有效经营槽到`.local-saves/v06`，新预览载入前回填；损坏/未来版本文件不覆盖。本地备份不上传Git。该宿主兼容层不修改Maker、服务环境或游戏文件沙箱；安卓仍使用原生存档，真机待验。
- 存档schema标记V0.6，不声称支持恢复V0.5内存进度（V0.5没有经营存档）。既有UI偏好文件独立保留；未来更高版本档案拒绝无提示降级读取。

## 9. 开发安排与配置责任

| 阶段 | 工作 | 完成标准 |
| --- | --- | --- |

存档数据设计从P1开始，不能到P5才发现机器锁/物品身份无法持久化。P1～P5可以按垂直切片交付，但没有用户新授权不提前实现本稿功能。普通策划、数值、代码、文档走LOCAL；预览等免费平台能力走MAKER-FREE，无需调用生成能力。

## 10. 验收覆盖与调参指标

1. 开始画面不跑营业；新游戏、继续、覆盖确认、返回标题和结束当天语义分明。
2. 准备阶段不产物、不出单、不计时；营业、暂停、归零整理、结算、次日与第10天总结状态正确。
3. 十天解锁及订单序列、容量上限、停单窗口、部分交付、目标/奖金与提前结束均按配置运行。
4. 36×28边界覆盖完整，店铺/镜头比例不变，入口不被堵死，大车间仍可读可操作。
5. 回收/购买/改线/绑定/卸载及重试不复制金币、唯一供货点、物品或建筑件数。
6. 第4～5天可形成有用实体物流，第6天只联网不自行运输，第7天实际入库计任务，第8天独立交付宿主可收银提交。
7. 统计只计真实新产出和交付；加量只在条件满足且玩家选择后次日生效，不暗改基本目标。
8. 读档恢复机器中途、带中货物、库存顺序、网络任务、断网等待、已发顾客单、部分交付收入和日奖励；未确认预览不变成实体。
9. 正常退出、异常中断、主档损坏/备份回退、重复读取、跨日、日初重试和未来schema拒读，均不破坏已有有效档案。
10. 真人记录每日日标达成时间、交付/分钟、搬运耗时、生产/堵塞时间、金币余额、购置支出和求助点。对比手工→传送带→电缆→交付的操作负担变化，而不只统计最终产量。
