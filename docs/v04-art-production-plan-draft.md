# V0.4 美术资产制作与接入计划（待用户确认）

> 范围更新（2026-10-18）：用户已明确首批只优先制作可操控四向纸片人员工与帧动画。当前执行策划请见[人物专项计划](v04-character-development-plan.md)；本文设备/环境/UI量产安排保留为后续候选，不作为本批开工范围。此前3D角色路线建议已由纸片人要求覆盖。

日期：2026-10-18。当前状态：只做规划，未授权开始生成资产或实现功能。按用户既定规则，正式制作前先取得并核对V0.4开发策划案；本文可作为填写和确认的草案。

## 1. 版本目标与边界

将V0.3白模Demo升级为风格统一、可识别、可实际加载运行的美术演示版本。交付以游戏内效果为准，概念图、生成完成和游戏内接入分别记录。

建议保持现有垂直正交镜头、世界比例、建筑占地/碰撞、接口网格、物品容量、生产时间、传送带规则和UI操作流程。素材按现有玩法适配；需要调整玩法或镜头时单列确认。新增经济、升级、联机和存档暂不纳入本版本。

现有素材：员工V3立绘、无道具三视图、四种面部表情、建筑工坊UI概念图。它们是设定/参考，尚未作为正式游戏表现接入；三视图不是动画帧，表情特写在垂直俯视下不作为优先制作项。

旧建筑UI概念图只参考配色与质感；布局和交互以V0.3已实现规范为准，不恢复旧版详情栏或旧确认流程。

## 2. 表现路线建议

建议采用“3D场景和设备 + Q版角色 + 手绘色块/简化贴图 + 2D UI”，延续当前3D逻辑、旋转、碰撞和建造预览。此路线尚待用户确认，不把原2D角色设定自动当作已批准的3D风格。

备选为2.5D贴片场景；如选择该路线，需先验证角色朝向、建筑四向表现、遮挡、阴影、投影与选取映射，再决定量产规格。

角色身份可沿用已确认的黑发黑瞳、深灰帽、黑黄制服、无固定手部道具。场景整体风格、设备轮廓和最终UI配色由样板确认；不直接混用各轮生成图的不同风格。

## 3. 开发安排与阶段验收

| 阶段 | 工作 | 交付物与完成条件 |
| --- | --- | --- |
| P0 需求与基线 | 收到V0.4策划案，确认表现路线、资产范围、参考、预算；复验V0.3的U06/U37/U38/U53或记录仍未通过项 | 已确认资产表、风格参考、优先级与验收标准；已知缺陷不混入美术验收 |
| P1 美术与加载样板 | 制作员工静态基础形、自动烹饪台、生/熟肉、地面样块及一组按钮/卡片样式；实际放入现有镜头 | 在游戏中检查比例、视角辨识、旋转、遮挡、可读性、手持与设备槽位；加载失败有白模回退；用户确认样板后量产 |
| P2 核心产线量产 | 五种物品、生产设备、供料点、三类接口、缓存台、传送带模块；每批生成后整理、适配、接入 | 完整汉堡链路使用新资产运行，生熟区分、端口方向、六槽与回堵状态可辨认；确认/取消与连续建造均正确 |
| P3 店铺与UI落地 | 手工设备、收银/交付/垃圾桶/区域入口、两区域环境；统一HUD、建造、物流、缓存、订单和生命周期页面的视觉 | 店内与车间风格一致；沿用V0.3布局和热区；图标具备必要文字说明，不将整张概念图当交互页面 |
| P4 动态表现与优化 | 员工待机/走/跑/持物，设备工作/完成反馈，传送带运动；按预算决定音效与BGM是否另做 | 动画只反映真实状态，不改变生产时长或交互；压缩/复用/资源尺寸经实测调整；缺失资源、重复切区和重开无表现残留 |
| P5 统一验收与归档 | Windows回归；具备测试包后进行小米14/Android15真机验收；整理授权、来源和积分记录 | 美术验收与玩法回归分别记录，Git版本可追溯；Android构建/发布按另行明确的请求执行，不在本规划阶段触发 |

P1是首个正式评审点。角色和设备样板未通过时，只修样板，不大批量制作其他资产。不同批次尽量复用材质、纹理和模块，避免批量生成后才发现俯视不可读。

不先承诺固定天数；P1通过、资源规格及工具交付能力确认后，再估算各批制作/修订/接入工作量。

## 4. 资产工作清单

数量按基础种类计，动画帧、四向变体、状态、纹理和LOD不包含在基础种类内；最终以已确认需求表为准。

| 优先级 | 分类 | 所需内容 | 制作注意 |
| --- | --- | --- | --- |
| P0 | 员工 | 1名员工基础外观；建议待机、走、跑、持物状态 | 先验证俯视下头、帽、身体、朝向与手持物的识别，三视图作为参考；手持物独立挂接 |
| P0 | 食材与成品 | 汉堡胚、生牛肉饼、熟牛肉饼、生菜片、汉堡，共5种 | 地面/手持/机器槽/传送带/缓存复用同一物品身份；生熟不能只靠微小色差 |
| P0 | 自动设备 | 自动烹饪台、自动汉堡组合台，共2种 | 保留各2.4×1.5占地及真实槽位/产出状态；四向旋转后仍可读 |
| P0 | 原料点 | 汉堡胚/生肉/生菜供料点，共3种表现 | 可共用主体，用外形标识/物品陈列区分；区分无限供料点和可取走的单件物品 |
| P0 | 缓存 | 缓存台1种、6槽选中/空/有物表现 | 保留2×4占地和真实槽位映射，选中高亮不遮物品 |
| P0 | 接口 | 十字、直通隔离、转角隔离，共3种 | 保留1×1占地；方向、合并/分流与隔离关系要清楚 |
| P0 | 传送带 | 直段、弯段、端头、方向标识及运输动态 | 按网格模块复用，适配不同长度；方向和真实货物分开表现，弯角/端口不能留断缝 |
| P1 | 手工设备 | 煎肉铁板、手工组合台，共2种 | 与自动设备轮廓明确区分；显示真实加工/材料状态 |
| P1 | 服务设施 | 收银台、交付区、垃圾桶、区域出入口 | 入口两区复用视觉语言；交付库存、垃圾桶功能不能混淆 |
| P1 | 环境模块 | 店铺/车间地面、边界/墙体、区域标识、少量装饰 | 先做可复用模块；装饰不得遮挡路径、物品或扩大实际不可通行区域 |

| P2 | 反馈与声音 | 完成/选中/非法位置/销毁等反馈；必要交互音效与BGM | 默认待确认；表情扩展、装饰特效、完整音乐可排后，不影响核心资产接入 |

## 5. 接入与文件规范

- 先建立资产表：资产ID、用途、版本、源图/提示词、文件路径、平台映射、许可来源、状态、尺寸/锚点、预算与验收结论。
- 推荐状态：待制作 → 待审 → 已确认 → 已适配 → 已接入 → 已验收，不能把“生成成功”当作接入完成。
- 世界逻辑与视觉节点分离。美术替换不改变原逻辑位置、碰撞盒、端口、缓存槽位与物品ID；根据实测模型边界确定缩放、枢轴、旋转及手持挂点。
- 建立统一资源映射与加载入口，复用同类资源，避免每帧重复加载。按入口/场景分批预加载，加载失败显示明确诊断并回退白模；具体策略在技术实现前核对Maker/UrhoX文档。
- 原始生成素材保留，发布用资源另存适配版本；图片透明边、裁切、模型比例、纹理朝向和动画循环都需要检查。
- Maker资产留在`assets/image`、`assets/model`、`assets/audio`等平台约定位置，保留远端来源映射。项目脚本引用按引擎资源根规则处理。
- 贴图建议从512/1024等级试起，重要近景再评估更高分辨率；面数、显存、包体和帧率预算根据P1实测确定，不预填已达标数字。
- 手机以小米14/Android15横屏为目标。Windows本地预览不能替代手机加载耗时、纹理内存、多指、后台恢复或发热测试。

## 6. 双线与积分安排

LOCAL负责规格、清单、代码、加载映射、资产整理、普通特效逻辑、测试与文档。Maker优先用于确定用途的高价值正式图片/模型/音频和平台专属处理；免费预览/调试按需使用。

余额、过期时间及真实扣费当前未在本轮查询，不能据此认定积分充足。制作前按可取得的真实余额安排批次与预算，先样板再量产；生成前提示、生成后记录实际数据，平台未返回则记未返回。工具要求的3D中间评审须由用户明确确认后继续。

## 7. V0.4统一验收重点

1. 当前垂直俯视下，员工/设备/原料/成品容易区分；两区域与UI风格一致。
2. 新资产与原位置、占地、四向旋转、碰撞、端口及选取范围一致；建筑名字/对象卡/手指标记仍对齐。
3. 同一物品在地面、手持、机器、带上和缓存中的表现一致，无悬空、穿模或遮住关键槽位。
4. 预览合法/非法、固定/跟随、选中/未选、可用/禁用等状态不只依赖颜色。
5. 新外观接入后取放、加工、连续建造、长按改带、缓存并发、跨区域生产及三天重开不退化。
6. 重复进入/退出区域和重开不会重复创建视觉节点或明显累积内存；资源缺失有回退。
7. 真机横屏可读、热区不缩小，记录实际帧率/加载/内存/发热；性能标准须在正式策划案中确认。
