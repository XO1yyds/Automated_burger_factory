# V0.4 下一阶段：UI美术替换与易读排版计划

日期：2026-10-19。状态：已获用户授权实施；素材与界面已接入，最终自检及交付状态见 `v04-ui-art-development-status.md`。

用户目标：UI使用与当前游戏相配的正式美术素材，重新整理为易读、清楚、有统一标准的版型。继续沿用已验收V0.6玩法与已接入静态美术；本阶段不恢复角色动画开发。

## 2. 统一视觉与组件

沿用现有员工和设备的手绘卡通风：奶油白内容面、湖蓝结构、暖橙主操作、炭黑轮廓，少量硬边阴影。正文使用高对比深色；深色遮罩内使用浅色文字。装饰避开正文和数字。

| 组件 | 统一标准 |
| --- | --- |
| 主面板 | 手绘边框+简洁浅色内容区；标题、正文、底部操作分区；高度按内容收缩，长内容只在内部滚动 |
| 按钮 | 暖橙主操作、湖蓝/浅色次操作、明确标识的危险操作；同屏主操作仅一个。继续/下一天等长文案保持文字 |
| 状态 | 常态、按下、选中、禁用、键盘焦点均明确；选中用边框+标识，禁用附原因，不依赖悬停或只靠颜色 |
| 卡片与物品行 | 左图标、中央名称/数量与必要说明、右侧动作；价格/容量采用固定次级行，不将全部信息写成一段 |
| 标签/分类 | 当前分类有明显底形和文字状态；横向滚动，右侧保留主操作空间，最后一张卡不被按钮压住 |
| 进度/槽位 | 真实进度、真实数量覆盖在美术底框上；空槽、缺料、处理中、受阻、成品可辨 |
| 弹窗 | 标题→简短说明→内容→固定操作区；确认在统一主操作位，返回/取消遵循原模式导航 |
| 文本 | 标题22–26、正文18、辅助16逻辑单位为推荐起点；过长名称最多两行，不以持续缩小字体解决拥挤 |
| 间距 | 采用8/12/16/24的间距阶梯；对齐图标、标题、数值和按钮，避免每页单独发明排列方式 |

文字、金额、数量、键位、订单进度全部由代码绘制，不烘焙进图片。面板/按钮使用透明PNG九宫格，保护边角与线宽；项目UI文档已有 `backgroundFit='sliced'` / `backgroundSlice` 支持。按钮热区独立于装饰图透明边界。

## 3. 默认版型与摆放

| 界面 | 默认排列 | 默认收起/隐藏 |
| --- | --- | --- |
| 正常HUD | 左上天数/阶段/时间+金币紧凑状态组，必要时第二行显示当日目标；右上订单摘要、暂停；左下摇杆与相邻手持卡；右下情境主动作，放下为次动作，建造在同组上方 | 正常模式无模式大标题、全宽配方条、生产状态长列表；教学和成功提示到时收起 |
| 目标检查 | 建筑上方单张信息卡，名称→关键状态→材料/进度；靠近/点选按原规则显示，贴边避让 | 非当前目标、历史操作、重复按钮隐藏；点击检查不允许远程取物 |
| 建造选型 | 顶部导航/模式；底部分类+横向建筑卡，右下独立“进入放置/布线/管理” | 设备运行详情与摇杆隐藏；不将所有分类卡强塞进一屏 |
| 放置/移动 | 顶部短标题；底部弱化重选条+旋转/确认；原因紧贴工具区上方，冲突仍在场景标出 | 不保留完整大分类栏；没有冲突时不占用一整行错误栏；点击场景不直接摆放 |
| 建筑管理 | 选中对象小卡+固定位置动作组；拆除与移动分开，返回在左上 | 未选中时不显示无关工具；拆除后仍留在管理模式 |
| 传送带 | 顶部“选A→选B→调整”步骤条；底部当前阶段工具；箭头/控制点在场景内 | 只显示当前步骤内容，不恢复旧设备下拉列表或链接列表 |
| 电缆 | 与传送带共用步骤条/工具栏/提示卡；保留金框插头，网络详情按需打开 | 普通游玩隐藏电缆；不把电缆图标误用成下单组件图标 |
| 缓存选物 | 保持场景六槽选物，统一选中框与物品卡，右下对应取出/交换/存入 | 不新增背包窗口；不把库存和缓存的交互混为一套 |
| 下单终端 | 标题/返回→下单、本机库存、网络、任务四标签→内容→固定主操作；物品行左图中说明右按钮；产品详情分配方、数量、可生产判断 | 配方详情、网络明细与历史任务默认折叠；没有内容时用简短空状态；任务取消保留 |

| 开始画面 | 复用现有背景，居中紧凑菜单；继续游戏为有存档时的主按钮，下方显示简短存档卡；新游戏/设置为次级 | 收掉大块无内容空白；覆盖存档的确认规则保留 |

## 5. 手机与Windows适配

- Android横屏，小米14/Android15为既定真机目标；Windows保留键鼠与快捷键标记。
- 1280×720仅作布局示意，使用逻辑单位、安全区与响应式布局，不锁定物理分辨率。
- 普通热区至少48×48，主操作至少104×48，间距至少12；美术装饰不扩大场景输入拦截区。
- 单套操作按钮按模式切换；手机隐藏无用键位字符，设置中原有双端/键鼠/触屏选择保持。
- 短高屏优先减少说明、折叠详情或启用滚动，保留返回、固定主操作与最小字体/热区。
- UI放大到1.2后检查长名称、四标签、数量选择和底部卡条；兼查16:9与长屏，不能把Windows缩小窗口当成真机验收。
- 摇杆、场景拖动、控制点拖动与滚动继续按现有触摸所有权规则；美术替换不引入一次点击同时选中和确认。

## 7. 验收标准

1. 首屏能够辨认天数/剩余时间、金币、订单摘要、手持物和当前可执行动作。
2. 正常HUD中，场景至少约75%的安全区面积不被不透明面板覆盖；作为原型检查目标，以所有面板覆盖面积的并集计，不计整屏交互层。弹窗与建造选型单独检查，不套此比例。
3. 同一时刻只有一个操作模式、一个目标检查卡和一个主要动作；普通成功提示约2秒收起，错误原因持续到修正或退出，拆除损失沿用原规则。
4. 面板无多余空白和文本裁切；长列表能滚动，按钮不随内容滚出，图标不拉伸、字体无烘焙和乱码。
5. 当前订单上限、十天进度、库存容量、载荷、金币、保存状态均来自真实数据。
6. 取物、交换、销毁、放置、旋转、拆除、传送带连续布置、网络任务取消、收银与保存等规则无回归。
7. 保留读档继续、保存返回和原进度；测试入口关闭。Windows画面通过与Android真机通过分别记录。

本计划中的版型、素材数量和尺寸为已补齐的推荐方案，可继续调整；目前没有必须由用户决定才能完成规划的阻塞项。已获得实施指令，按批次推进并最终统一验收。

## 8. 窗口与镜头适配补充（2026-10-19）

用户提出让UI图层随镜头可视范围适配。本轮采用以下实现边界：

- HUD、弹窗、建造卡条、操作按钮依附当前屏幕安全区，尺寸取自 `graphics:GetWidth()/UI.GetScale()` 和对应高度，并扣除安全区；窗口变化和UI缩放后自动重新布局。
- 镜头平移、世界缩放不改变文字字号与按钮热区；这避免手机操作按钮随世界镜头缩小。
- 建筑昵称和目标检查卡保留世界坐标锚点，再通过当前镜头投影到屏幕，并避让UI边缘；不改为固定镜头位置的建筑标签。
- 原生检查工具只观察真实窗口，不在正式入口或绘制阶段强制1280×720等测试画布。隔离工厂与检查入口在交付时关闭。
- 真实窗口显示、逻辑受限画布检查、Android真机检查分别记录，不将其中一种当成另一种完成。
