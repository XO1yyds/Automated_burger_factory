# V0.5 库存与依附组件修订

依据：用户本轮6项设定及随后确认。延续V0.5，不扩展V0.4美术工作。

## 已确定规则

- 普通库存与交付终端：空手取栈顶；持物拒绝交互；禁止玩家存入或交换，允许传送带、电缆输入输出。缓存台原有选槽取换/空槽存入保留。
- 下单组件只依附现有库存；交付组件依附库存或缓存台。每个宿主最多一种组件，不可叠加。仅改变外观/名称/交互，不改变宿主ID、容量、占地、旋转、端口或原有内容。
- 下单终端交互打开下单页面，取消直接空手取物。新增“本机库存”页，可查看并任取选中物品，每次1件；普通库存与自动出库仍遵守原有栈规则。
- 已确认：手满时取出的物品落在附近，原手持不变；地面无合法空位时整次拒绝，库存与手持均不变化；不销毁物品腾位置。
- 下单成品固定进入绑定库存；取消旧版另选成品目标的流程。进度统计下单之后匹配物品的实际入库事件，传送带与电缆均有效；原有存量、查看页面、生产完成但尚未入库不计到货。
- 同一物品循环回库不重复计同一任务。多任务按提交顺序分配匹配到货，一件物品不同时完成多个任务；进度达到需求即完成，不要求成品继续留库。
- 网络改动不取消、重置或改写已提交任务；实际运输仍校验当前连接，不跨断线凭空配送。任务可等待，保留同行主动取消；取消后停止新投料，已有加工安全收尾。
- 交付终端沿普通库存交互；交付缓存沿缓存台交互。收银页汇总所有仍存在的交付宿主，不要求接入电缆；按订单品类取用，可越过非目标物品，仍尊重任务物品锁定。
- 保留店内原交付区域；收银交单同时可取原交付区与交付组件物品，不复制到虚拟库存。只消费订单实际需要的数量，继续允许部分交付。

## 推荐补齐

- 建造组件流程：选组件 → 点选兼容宿主 → 明确点击“确认绑定”；不创建独立地面建筑；可连续绑定。
- 设备管理增加“卸下组件”，保留宿主与内容。卸下下单组件先确认并取消任务；拆宿主时同时卸组件，物品仍走现有拆除落地规则。
- 原示例独立下单组件取消；初始成品库存附下单组件，成品缓存附交付组件。每网至多一个下单终端的规则保留，绑定前校验。
- 本机库存按品类显示数量，点“查看”进入品类详情，再点“取出1件”；每次确认重新核对真实物品与空间，防止页面显示后被物流取走导致重复取出。
- 顶部固定页签为“下单 / 本机库存 / 网络 / 任务”，保持现有48逻辑单位按钮及滚动标准。任务统一使用“到货进度”。
- 普通玩法、组件页面、收银页面统一以真实容器数据刷新；取消/结算/暂停/重开仍沿既有生命周期。

## 开发与验收范围

1. 存储只取规则、入库事件及物流传递身份。
2. 组件宿主绑定/互斥/卸载、外观、占地与端口保留。
3. 绑定库存下单、双运输到货计数、断网保留/主动取消。
4. 本机库存查看、任取及手满/地满保护。
5. 交付组件同步、按品类扣减、旧交付区兼容。
6. Lua领域与运行集成、Windows UI检查、普通开局恢复与人工验收清单。手机真机仍须单独验收。

以本稿覆盖旧V0.5中的独立2×2组件、任意成品目标、库存手动存换，以及仅任务自身电缆交付才计完成的规则。通用工程走LOCAL，预览走MAKER-FREE，不调用Tap生成能力，不远端构建或上传。
