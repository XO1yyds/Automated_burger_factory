# 自动化汉堡店建筑放置 UI 修改建议清单

## 一、整体目标

参考《明日方舟：终末地》基建 UI 的交互结构，将当前偏“测试工具式”的建筑与物流界面，调整为“场景驱动、模式切换、情境操作、信息分层”的工业建造 UI。

核心原则：

- 场景始终是视觉主体。
- UI 只负责表达当前模式、当前选中对象、可执行操作和异常反馈。
- 正常游玩、建筑放置、建筑管理、传送带布置使用不同的操作状态。
- 不照搬《终末地》的美术，只借鉴其交互结构和信息组织方式。
- 保留当前玩法逻辑，不额外加入金币、升级、解锁、背包等不存在的系统。

---

## 二、正常游玩 HUD

### 1. 精简常驻信息

建议删除或折叠以下内容：

- 版本号
- 完整键盘说明
- 累计交接件数
- 大量测试状态文字

常驻信息只保留：

- 天数 / 倒计时
- 订单摘要
- 当前手持物
- 暂停入口
- 建造入口

### 2. 订单显示简化

当前右上常驻 5 条订单列表建议改为：

- 默认只显示订单摘要，例如“订单 0/5”
- 点击后展开详细订单信息

### 3. 设备信息改为情境显示

自动设备的材料、进度、待取状态：

- 靠近设备时显示
- 选中设备时显示
- 不长期堆叠在左上 HUD

---

## 三、建造模式入口

### 4. 增加独立建造入口

正常游玩时增加明显的“建造”按钮。

点击后：

- 进入建造模式
- 场景继续保持可见
- 可适当拉高镜头
- 显示建造网格
- 顶部显示当前模式

例如：

- 建造模式
- 正在放置：自动烹饪台
- 建筑管理
- 传送带 · 选择起点
- 传送带 · 选择终点
- 传送带 · 调整路径

### 5. 不再依赖键盘说明表达当前模式

手机端不应再主要依赖：

- B 建筑
- ESC 返回
- Tab 管理
- F 确认

Windows 键鼠操作保留，但手机端必须有可见按钮。

---

## 四、建筑选择界面

### 6. 取消中央纵向大面板

当前建筑选择界面建议由中央纵向按钮改为底部横向建筑栏。

### 7. 建筑分类

建议分为：

#### 生产

- 自动烹饪台
- 自动汉堡组合台

#### 接口

- 十字拓展接口
- 直通隔离接口
- 转角隔离接口

#### 物流

- 传送带

#### 储存

- 缓存台

#### 管理

- 已有建筑 / 传送带管理

### 8. 建筑项表现

建议采用：

- 图标
- 建筑名称
- 明确选中状态

暂时不要增加：

- 金币
- 建筑价格
- 等级
- 解锁条件
- 升级
- 数量限制

---

## 五、建筑放置模式

### 9. 选中建筑后收起建筑菜单

进入建筑放置后：

- 底部建筑选择栏隐藏或弱化
- 场景成为主要操作区域

只保留少量高频操作：

- 旋转
- 确认摆放
- 取消

### 10. 保留“固定投影”和“正式建造”的区分

当前逻辑应继续保留：

- 固定投影 ≠ 正式建造
- 必须通过独立“确认摆放”按钮正式建造

### 11. 强化建筑投影反馈

#### 合法位置

- 建筑投影显示绿色
- 地面格子正常高亮
- “确认摆放”按钮可用

#### 非法位置

- 建筑投影显示红色
- 冲突格单独高亮
- 显示简短原因

例如：

- 与建筑重叠
- 超出建造区域
- 当前设备正在加工
- 已连接传送带，无法移动

### 12. 减少长文字提示

原则：

- 场景负责告诉玩家“哪里错了”
- 文字负责告诉玩家“为什么错”

---

## 六、建造网格

### 13. 网格仅在编辑状态显示

建议在以下模式显示网格：

- 建筑放置
- 建筑管理
- 传送带布置

正常游玩时：

- 隐藏
- 或保持极淡

### 14. 网格承担空间反馈

网格需要辅助表达：

- 建筑占地
- 对齐关系
- 接口位置
- 冲突格
- 可放置范围

---

## 七、建筑管理模式

### 15. 建筑管理改为直接点场景对象

进入“管理”模式后：

- 点击已有建筑直接选中
- 建筑高亮
- 不打开大型管理窗口

### 16. 管理工具栏

选中建筑后底部显示：

- 移动
- 旋转
- 拆除
- 返回

### 17. 拆除防误触

拆除属于高风险操作：

- 与普通操作按钮保持足够距离
- 明确显示拆除状态
- 如有物品损失，需清晰反馈

---

## 八、建筑状态信息

### 18. 使用场景情境信息卡

建筑状态不应全部塞进 HUD。

建议选中设备后，在设备附近显示小型状态卡。

例如自动烹饪台：

- 生肉槽状态
- 加工进度
- 熟肉待取状态

例如自动组合台：

- 汉堡胚
- 熟牛肉饼
- 生菜片
- 加工进度
- 成品待取

### 19. 未选中时隐藏详情

只保留必要的场景状态表现，避免全屏同时显示所有设备详情。

---

## 九、传送带模式

### 20. 传送带独立成连接模式

点击“物流 → 传送带”后：

- 隐藏普通建筑放置工具
- 进入专门的传送带模式

整个流程拆成三个阶段：

1. 选择输出端 A
2. 选择输入端 B
3. 调整路径

### 21. 当前阶段必须明确

顶部显示：

- 传送带 · 选择起点
- 传送带 · 选择终点
- 传送带 · 调整路径

玩家任何时候都应该知道当前处于哪一步。

---

## 十、传送带 A/B 选择

### 22. 选择 A 时

- 只高亮可作为输出端的对象
- 点击后保持 A 的高亮
- 显示已选择对象

### 23. 选择 B 时

- 只高亮可作为输入端的对象
- A 到当前位置显示实时预览路径
- 移动到合法 B 时吸附到建筑接口

### 24. 避免空白点击产生误导

点空白区域时：

- 不应误判为已选 B
- 明确保持当前选择阶段

---

## 十一、传送带路径调整

### 25. 直接在场景内编辑

进入路径调整后显示：

- 端点控制点
- 转角控制点
- 直线段控制点
- 当前选中控制点
- 运输方向箭头

### 26. 控制点状态清晰

需要区分：

- 未选中
- 当前选中
- 可移动
- 受限
- 非法

### 27. 工具栏简化

建议仅保留：

- 反转方向
- 确认
- 取消 / 返回

当前只有基础传送带，因此不要把“类型”设计成已有多种带可切换。

---

## 十二、非法线路反馈

### 28. 合法路径

- 绿色
- 方向箭头正常
- 确认按钮可用

### 29. 非法路径

- 红色
- 冲突节点单独高亮
- 确认按钮禁用
- 显示一句简短原因

例如：

- 与建筑冲突
- 接口已占用
- 无法保持连接
- 路径不合法

### 30. 衔接格规则暂不提前做死

“衔接格后第一格”如何处理目前仍未确定。

因此 UI 只先表现：

- 该位置受限
- 当前无法拖动 / 调整

不要提前做成：

- 自动补线
- 强制锁定
- 自动重连

除非后续正式确认。

---

## 十三、确认与返回逻辑

### 31. 确认操作统一

建议：

- 建筑正式摆放：确认摆放
- 传送带正式落地：确认
- 建筑管理完成：确认 / 完成

避免部分操作单击即生效、部分操作需要二次确认。

### 32. 返回层级统一

推荐：

- 路径调整 → 选 B
- 选 B → 选 A
- 选 A → 建造首页
- 建造首页 → 正常游玩

手机端需要可见返回按钮。

Windows 端继续保留：

- ESC
- 右键

但不作为唯一入口。

---

## 十四、缓存台

### 33. 保持场景内交互

缓存台不新增传统库存弹窗。

继续采用：

- 直接点击台面六个槽位
- 当前槽位高亮
- 场景中直接显示物品

### 34. 根据手持状态决定操作

#### 空手 + 有物槽

- 取出

#### 持物 + 有物槽

- 交换

#### 持物 + 空槽

- 存入

#### 空手 + 空槽

- 失败提示

### 35. 三种容量保持独立

必须明确区分：

- 玩家手持：1 件
- 缓存台：6 件
- 交付区域：5 个汉堡

不要整合成统一背包。

---

## 十五、提示信息系统

### 36. 减少底部长条说明栏依赖

当前底部说明栏承担信息过多。

建议拆分为：

#### 顶部

显示当前模式。

#### 场景附近

显示当前目标名称、设备状态。

#### 右下 / 底部

显示当前可执行操作按钮。

#### 屏幕中下方

显示短时反馈 Toast。

例如：

- 已放置
- 空间不足
- 无法连接
- 物品已被输出
- 当前槽位为空

---

## 十六、信息层级

### 37. 长期信息

长期显示：

- 天数
- 倒计时
- 订单摘要
- 手持物
- 当前模式

### 38. 情境信息

按需要显示：

- 当前建筑名称
- 当前设备详情
- 当前缓存槽
- 当前连接对象
- 当前控制点

### 39. 短时反馈

操作后短暂出现：

- 放置成功
- 连接失败
- 空间不足
- 拆除损失
- 选择失效

三类信息不要混在同一个固定面板中。

---

## 十七、移动端触屏布局

### 40. 正常游玩

建议：

#### 左下

- 虚拟移动摇杆

#### 右下

- 情境交互按钮
- 放下按钮

#### 右侧 / 右下

- 建造入口

#### 顶部

- 时间
- 订单
- 暂停

### 41. 建筑放置模式

操作区替换成：

- 旋转
- 确认摆放
- 取消

### 42. 传送带调整模式

操作区替换成：

- 反转方向
- 确认
- 返回

不要让所有模式按钮同时常驻。

---

## 十八、触屏防误触

### 43. 主要按钮扩大点击热区

特别是：

- 确认
- 取消
- 拆除
- 旋转

### 44. 高风险按钮保持距离

避免：

- 确认和取消挨得过近
- 拆除和移动挨得过近

### 45. UI 点击禁止穿透

点击 UI 时不能同时触发：

- 场景选中
- 建筑摆放
- 角色交互
- 传送带节点编辑

### 46. 手指遮挡处理

拖动建筑或控制点时：

- 投影位置适当偏离手指
- 关键提示不要出现在手指正下方

### 47. 区分不同拖动操作

需要明确区分：

- 镜头拖动
- 建筑拖动
- 控制点拖动
- UI 滑动

---

## 十九、优先开发顺序

### 第一优先级

先完成：

1. 正常 HUD 精简
2. 建造入口
3. 底部建筑选择栏
4. 建筑放置工具栏
5. 建筑合法 / 非法反馈
6. 传送带三阶段流程
7. 传送带路径调整

### 第二优先级

继续完成：

1. 建筑管理
2. 建筑情境详情
3. 缓存台触屏交互
4. 非法状态反馈
5. 返回层级统一

### 第三优先级

最后统一：

1. 收银 UI
2. 暂停 UI
3. 每日结算
4. Demo 完成页面
5. 触屏操作教学
6. 触控设置

## 二十、首批原型建议

第一阶段只优先制作三个原型画面：

### P01：正常游玩

验证：

- HUD 信息量
- 移动与交互按钮位置
- 订单摘要
- 建造入口

### P04：建筑放置

验证：

- 建筑选择后的场景占比
- 投影
- 网格
- 旋转
- 确认
- 取消
- 非法反馈

### P08：传送带调整

验证：

- A/B 选择流程
- 路径预览
- 控制点
- 运输方向
- 精确调整
- 受限位置反馈
- 确认 / 返回

这三个界面确认后，再将同一套设计语言扩展到其他页面。

## 二十一、最终设计方向总结

修改后的建筑放置 UI 不应继续以“大量黑色信息框 + 键盘操作说明”为核心，而应逐步转为：

> **场景驱动的工业建造 UI。**

玩家主要直接操作场景中的：

- 建筑
- 网格
- 接口
- 传送带
- 控制点
- 缓存槽

UI 只辅助表达：

- 当前是什么模式
- 当前选中了什么
- 下一步可以做什么
- 当前操作是否有效
- 为什么无法操作

最终目标是让玩家的注意力主要停留在自己搭建并实际运行的汉堡生产线上，而不是停留在菜单和说明文字上。
