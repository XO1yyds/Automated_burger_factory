## 1. 目标与运行环境

- Windows 本地窗口预览，键盘与鼠标操作；本版本不要求手机触控或远端 Web 验收。
- 单人、单房间白盒场景，按最新参考图采用纯俯视正交表现；不引入多人大厅或新玩法系统。
- 镜头按 [图 1](references/camera-topdown.png)：垂直向下（俯角 90°）、正交无透视、不可旋转，只支持缩放和平移。WASD 以屏幕方向移动，W 向屏幕上方。运行层保留基础几何体和碰撞，显示效果为 Top-down 平面视图。
- 地图按 [图 2](references/map-layout.png)：左上自动化区域入口；顶边从左到右为组合台、煎肉铁板和三种无限原料点；左侧垃圾桶；下方收银台与其右侧交付区。具体白盒坐标见 [布局确认](phase1-layout-update.md)。此决定覆盖原文等轴测镜头及初版布局。
- Phase 1 中入口仅为位置标记，垃圾桶仅为白盒实体，不增加传送、切换房间或垃圾处理玩法。
- 使用基础几何体、纯色与文字标签。保留原文全部排除项，不生成正式美术、音乐或音效。
- 地图尺寸、移动速度、白盒配色在开发时按场景适配，不做正式数值平衡。

## 2. 每天的订单与结束条件

| 项目 | 已确认规则 |
| --- | --- |
| 每天时长 | 5 分钟，共 3 天 |
| Day 1 订单 | 每单固定 1 个汉堡 |
| Day 2 订单 | 每单随机 1～2 个汉堡 |
| Day 3 订单 | 每单随机 1～3 个汉堡 |
| 订单间隔 | 随机 5～15 秒，首单也等待此间隔 |
| 最大订单数 | 最多 5 个未完成订单；满单暂停生成；腾出位置后重新随机等待 |
| 当日计时归零 | 立即停止生成订单，立即清除全部未完成订单，清除收银界面对应选择；不产生失败、惩罚或完成统计 |
| 计时归零后的活动 | 可继续移动、使用机器、搭建建筑及整理场景，直到玩家主动结束当天 |
| 暂停菜单“结束当天” | 可以随时使用，包括计时尚未归零时；直接结束当天并进入结算 |
| 收银台“结束当天” | 仅在当日计时归零后可用，禁止通过此入口提前结束 |
| 提前结束当天 | 停止当天模拟并进入结算，清除未完成订单，不把清除记作完成或失败，不跨日保留订单 |
| 倒计时含义 | 无订单倒计时；保留 HUD 当日剩余时间 |
| 下一天 | 结算后进入；重置当天计时、订单生成等待及当日统计 |
| 第三天结束 | 进入 Demo 完成界面，可重新开始或退出 |

## 3. 交互与生产边界

- 保留原文：单手仅持 1 件物品、5 种物品、3 个无限原料点、F 前方最近有效交互、Q 丢物、约 1 格交互距离。
- 用户修订 Phase 2：持物 F 与地面物品互换，旧物留在地面原位置；用户已确认原料点互换时旧物放附近有效地面后取得新原料，无空位则不交换。此规则覆盖原文“手上已有物品不能继续取料”。地面物品名称改为对准时在屏幕上侧正中显示，取消其世界坐标悬浮标签。
- 用户在 Phase 3 修订建筑名称：靠近建筑时，建筑屏幕轮廓的正上方留 5px 显示小字名称；离开后隐藏。实现参数：到建筑占地边缘约 1 格内显示，不要求面向；字号为 12 个 UI 基准像素，标签下边缘到建筑屏幕上边缘为 5 个物理像素。原料点也使用这一建筑名称规则，不再在上侧正中重复显示；地面物品保留上侧正中对准名称。
- 用户要求场景比例恢复到建筑标签修复前：撤销强制 `autoAspectRatio=false` 和显式 `camera.aspectRatio` 写入，恢复原相机默认比例行为；原 `orthoSize`、滚轮缩放、中键平移参数保留。此前标签六项几何检查来自强制宽高比版本，不能用于证明恢复后的标签对齐。
- 最新昵称规则覆盖屏幕标签方案：建筑昵称必须是场景中的 `Text3D` 子节点，位于建筑上边缘外侧的固定世界坐标锚点；与建筑移动、旋转和镜头缩放一致，靠近时显示，不能为了昵称改场景比例。屏幕 5px 间距随缩放变化，以最新“相对建筑固定”的要求为准。
- 手工煎肉：放入生肉后重新长按 F，连续 3 秒完成。松开 F 或离开交互范围则进度归零，肉仍留在铁板上；加工时不能取出。
- 自动烹饪台：总共3个槽位，分别独立计时3秒；熟肉留在原槽并占位。空手优先取最早完成熟肉；没有熟肉时，生肉按后进先出取回，再投入进度清零。
- 手工组合台：正确三种材料齐全立即生成汉堡；未加工时允许空手取回未合成材料，成品优先取出。
- 自动汉堡组合台：允许生肉占肉槽，但不触发配方并显示缺少熟肉。未加工时空手可取回材料；正确材料齐全后加工 2 秒，加工时禁止取料；成品缓存 1 个，成品优先取出，未取走时不启动后续加工。
- 汉堡配方仍为汉堡胚、熟牛肉饼、生菜片各 1 份。生肉不能代替熟肉。

## 4. 建造与物品放置

- 保留两种免费可建造建筑：自动烹饪台、汉堡组合台；不增加购买、成本或升级。
- 建筑菜单选型后直接进入可定位、旋转和确认放置的预览，支持键鼠；取消独立准备放置状态。确认后保留当前类型、朝向与位置，可连续建造。
- 两种设备使用非正方形占地，让旋转能明显改变布局；具体占地尺寸属于实现参数。
- 建筑模式中的新建、选择、移动、删除取消全部五格限制。整个占地仍须合法，不能越界或重叠建筑、入口、玩家、地面物品；普通F前方交互仍约一格。
- 建筑模式下，已有建筑支持鼠标选择和键盘 F 选择前方建筑。与建筑选型菜单使用独立输入状态，避免一次 F 同时选型、移动或确认。
- 选中已有建筑后复用准备放置操作；加工中不能移动或删除。取消移动恢复原位置和朝向；移动保留原料与成品。
- 非加工建筑删除时，内部物品掉落到附近有效地面；不得无提示吞掉物品。建筑模式 Q 只执行删除，普通模式 Q 才丢弃手中物品。
- Q 丢物寻找附近有效地面，不穿入建筑、不丢出地图；没有有效位置时保留手中物品。

## 5. 收银与交付

- 收银台固定，交付区域独立，容量最多 5 个汉堡。
- 手持汉堡按 F 放入交付区域；空手按 F 可以取回汉堡。
- 收银界面必须主动选择订单，补充键盘选单与确认操作，同时保留鼠标操作。
- 一次交付数量为 `min(交付区汉堡数量, 所选订单剩余需求)`；支持部分交付，不超额扣除，多余汉堡保留。
- 未选订单、交付区空或订单已移除时不能交付。订单完成即移除并清除其选择，不自动向另一订单交付。
- 当日时间归零即清除未完成订单；此后没有旧订单可继续交付，交付区剩余汉堡仍保留。

## 6. 暂停、跨日与统计

- 暂停菜单和结算界面暂停模拟：玩家、加工进度、当天计时和订单生成均停止。
- 建筑菜单、建筑放置模式和收银界面锁定玩家移动，但机器、当天时间和订单生成继续运行。退出后恢复普通交互。
- 建筑子界面ESC回建筑主界面，主界面ESC退出建筑模式，再次ESC暂停；右键逐层回退。已有建筑移动/删除成功后回管理，可继续选择。
- 跨日保留建筑、机器材料、成品、机器加工进度、地面物品、交付区汉堡及玩家手持物品。订单不跨日。
- 当日完成订单数量在订单完整交付时计数；清除的订单不计数。
- 当日制作汉堡数量在汉堡生成时计数，按最终组装设备分为手工或自动；自动煎肉后手工组装仍计为手工汉堡。
- 不做存档。重新开始清空地图动态状态、建筑、物品、订单、进度和统计，回到 Day 1。
- Windows 本地预览的“退出游戏”关闭游戏窗口；不增加 Web 退出流程。
