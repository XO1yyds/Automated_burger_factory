# 自动化汉堡店：当前画面信息与 UI 原型说明

日期：2026-10-18  
范围：Demo V0.2 当前实现。依据当前脚本核对信息和操作状态，不代表本轮逐像素截图验收。  
用途：帮助阅读现有画面、拆分信息层级、绘制 UI 原型；手机建议单独标注，不视为已开发或已确认交互。

## 1. 游戏是什么

玩家在汉堡店取原料、加工和组装汉堡，将汉堡放入交付区域，再通过收银台主动选择订单并交付。玩家也可以进入独立自动化车间，建造设备、接口、缓存台和实体传送带，让原料经过加工和运输后成为汉堡。

- 镜头：垂直俯视、正交投影；可平移和缩放，不旋转。
- 场景：汉堡店、自动化车间，各 18×14 米；当前比例保持。
- 手持：最多 1 件；原料点与地面物品支持持物交换，没有玩家背包页。
- 物品：汉堡胚、生牛肉饼、熟牛肉饼、生菜片、汉堡。
- 配方：汉堡胚 + 熟牛肉饼 + 生菜片，各 1 件。
- 三天体验：每天 300 秒。计时归零清除未完成订单，场景仍可继续整理；结束当天需主动操作。
- 自动化成品进入缓存台，不自动计入店铺交付库存；仍需取出、携带并放入交付区域。

核心流程：

```text
取原料 → 手工/自动加工 → 组装汉堡 → 手持搬运 → 交付区 → 收银选单交付
                    自动化链路：原料 → 传送带 → 机器 → 传送带 → 缓存台
```

## 2. 当前正常画面的区域划分

以下是当前桌面布局；手机原型可重排位置，保留信息含义，不照搬全部文字栏。

| 区域 | 当前显示 | 功能 | 出现条件 |
| --- | --- | --- | --- |
| 左上信息栏 | 版本标题、日期/时间、今日统计、键盘说明、手持物、工作台状态、自动设备状态、交付库存 | 集中显示游戏与生产信息；目前含大量测试文字 | 正常场景基础层 |
| 右上订单栏 | “当前未完成订单”，最多 5 条订单及交付进度 | 看还有哪些订单未完成；此栏本身不能点击选单 | 有订单时显示对应行 |
| 上侧正中 | 当前对准的地面物品名称 | 辨认拾取/交换对象 | 有地面物品目标时；不是建筑统一昵称栏 |
| 底部提示栏 | 当前操作提示、操作结果；无短时结果时显示配方说明 | 说明现在能做什么、刚才发生了什么 | 随目标与操作模式变化 |
| 右下区域信息 | 当前区域、B建筑提示、实体带总数、累计交接件次 | 确认所在区域及物流概况 | 基础层；件次是物流交接计数，不是汉堡产量 |
| 中央场景 | 玩家、设备、原料、地面物品、传送带货物、入口标记 | 游戏实际操作空间 | 当前区域可见 |
| 建筑附近 | 建筑名称、交互高亮、设备/缓存中的实体内容 | 辨认建筑、当前目标与库存 | 名称靠近显示；交互高亮对应当前目标 |
| 模式面板 | 建筑选择、管理、施工工具栏、收银或生命周期面板 | 执行具体操作 | 进入相应状态后出现 |

## 3. 场景内容与玩家可执行功能

### 3.1 汉堡店

| 场景对象 | 功能 | 原型需要表达的重点 |
| --- | --- | --- |
| 汉堡胚、生牛肉、生菜原料点 | 无限取料；持物交互可换成该原料，旧物尝试落地 | 当前原料名称；获取或交换动作 |
| 煎肉铁板 | 放入生肉，空手连续按住交互 3 秒加工；中断则进度清零，完成后取出 | 空槽、加工剩余时间、持续操作、完成待取 |
| 手工组合台 | 每种正确材料最多 1 份；齐全后直接生成 1 个汉堡 | 三种材料需求、完成后空手取出 |
| 自动烹饪台 | 三槽独立加工，每槽 3 秒 | 三槽空/加工中/熟肉；手动取出生肉后进先出 |
| 自动汉堡组合台 | 材料齐全后加工 2 秒，成品缓冲 1 件 | 缺料、加工中、成品待取；加工中禁止投入/取回 |
| 交付区域 | 存入/取出汉堡，库存容量 5 件 | 与手持、缓存台的库存区分 |
| 收银台 | 打开订单操作面板，主动选单并交付 | 不是靠近后自动交单 |
| 垃圾桶 | 销毁当前手持物，包含汉堡 | 销毁动作及目标明确；空手无物可销毁 |
| 自动化区域入口 | 携带手持物进入车间 | 当前目的地与进入操作 |

### 3.2 自动化车间

| 场景对象 | 功能 | 原型需要表达的重点 |
| --- | --- | --- |
| 三类供料口 | 提供汉堡胚、生肉、生菜 | 原料类型、作为输出端接带 |
| 烹饪台与组合台 | 自动加工 | 输入需求、进度和成品状态 |
| 基础传送带 | 单输入单输出，主动运输，不过滤；0.5 格/秒 | 明确方向、可见在途物品、排队回堵 |
| 十字拓展接口 | 被动合并/分散，不另设库存 | 接入方向，允许组合；普通 2进2出不允许 |
| 直通隔离接口 | 上下/左右组成独立通道 | 通道颜色及配对，不串料 |
| 转角隔离接口 | 两组转角独立通道，随旋转改变配对 | 通道配对和旋转结果 |
| 缓存台 | 2×4 格、6 件容量，可输入输出；输出后进先出 | 六槽库存、当前选槽、取出/交换/存入 |
| 返回汉堡店入口 | 携物返回店铺，离开后车间继续模拟 | 返回动作，不误显示为停机 |

## 4. 建筑与物流的模式画面

### 4.1 建筑选择

- 当前位置：屏幕中部，偏上；深色面板和纵向文字按钮。
- 标题：建筑选择 · 免费 / 无数量上限。
- 六种建筑：自动烹饪台、自动汉堡组合台、十字拓展接口、直通隔离接口、转角隔离接口、缓存台。
- 其他入口：传送带布置、管理已有建筑/传送带、退出建筑模式。
- 选择反馈：按钮文字前显示“已选”。
- 功能限制：接口和缓存台在车间建造，传送带也仅在车间布置；当前面板不应被理解为所有按钮在店内均可放置。
- 当前没有金币价格、解锁条件、升级或购买数量 UI。

### 4.2 建筑放置/移动

| 信息或元素 | 当前表现与功能 |
| --- | --- |
| 建筑投影 | 跟随定位，按网格移动；绿色表示合法，红色表示非法 |
| 固定状态 | 场景左键固定；移开鼠标投影保持；空白处再次左键解除 |
| 微调和旋转 | WASD 微调；旋转使用现有键鼠操作，手机按钮尚未制作 |
| 确认摆放 | 使用独立确认按钮；固定投影不等于建造 |
| 取消 | 工具栏“取消布置”；右键按层回退，ESC回建筑首页 |
| 合法性说明 | 底部显示可放置或具体失败原因；没有五格放置距离限制 |
| 连续建造 | 新建成功后留在预览状态，可继续放置 |
| 设备移动限制 | 已接带需先拆相关带；加工中不能移动；限制需反馈 |

当前普通建筑预览工具栏主要显示“确认摆放”和“取消布置”。旋转、删除、回退等不少动作仍依赖文字提示和键盘，并非都已做成独立按钮。

### 4.3 建筑/传送带管理

- 管理提示区位于左下，显示选取、删除与返回说明，以及“返回选型”“退出”按钮。
- 点选建筑进入移动/处理状态；可移动、旋转或删除，遵守连接与加工限制。
- 点选传送带选择整条带，显示带编号与拆除提示；当前不支持对运行中的带直接重调路径或改向。
- 处理完仍留在管理状态，方便继续选取。
- 拆带按队列顺序尝试落地；空间不足仍拆除，并明确报告实际删除物品内容和数量。

### 4.4 传送带：选择 A → 选择 B

| 阶段 | 画面必须表达 | 当前功能 |
| --- | --- | --- |
| 选 A | “选择输出建筑 A”、场景选择光标 | 点建筑或键盘光标选择；此时尚未确定输入端 |
| 选 B | “选择输入建筑 B”、A 到当前位置的跟随路径 | 移到建筑 B 时贴合其边框；点空白不成为正式 B |
| 通用 | 取消布置及逐级返回提示 | 选择建筑本体，不使用旧上下游列表 |

### 4.5 传送带：路径调整

- 场景：预览路径、黄色运输方向箭头、端点/转角控制点、直线路段控制点；选中目标高亮。
- 颜色：合法预览绿色，非法预览红色；当前控制点以蓝色/青色及选中白色区分。
- 工具栏：确认摆放、反转方向、类型：基础带、取消布置；本期只有基础带，类型按钮不代表已有多个选项。
- 提示：当前是在选择节点/路段，还是正在编辑；显示合法性原因。
- 操作：编辑端点、转角或整段直线，保持网格、直角及建筑连接；存在衔接约束。
- 受限情况：衔接格后第一格拖动可能破坏连接；如何锁定、提示或补线仍待策划确定，不能在原型中标成已完成。
- 确认成功后：进入下一轮选 A，支持连续布线。
- 返回：调整 → 选 B → 选 A → 建筑首页；ESC直接回建筑首页。
- 当前没有单独的按带点选详情面板，也未将缺料/堵塞等所有网络内部状态制作成场景图标。

## 5. 缓存台选择画面

- 保留游戏场景，不打开新的库存面板。
- 台面六槽默认排列为 2列×3行，随建筑旋转；可看见槽内实体物品。
- 当前选槽使用黄色高亮，空槽也可选择。
- 底部提示字段：缓存槽编号/6、该槽物品或“空”、可执行操作、取消方式。
- 首次交互先进入选槽；键盘选择后 F 执行；当前桌面鼠标点槽直接执行。
- 空手+有物槽：取出；持物+有物槽：交换；持物+空槽：存入；空手+空槽：失败提示。
- 成功后退出选择；取消不转移物品。
- 选物期间产线继续，选中物被输出带取走后提示重新选择。
- 手机进入选择、点槽执行与手势区分，仍需在手机策划案中确定。

## 6. 收银、暂停和结算画面

| 画面 | 显示信息 | 当前操作与关键状态 |
| --- | --- | --- |
| 收银台 | 标题、最多5个订单按钮、所选订单、交付库存 | 选单、交付所选订单、结束当天、关闭；未选单或无法交付时按钮禁用 |
| 收银结束当天 | 按钮及可用性说明 | 仅计时归零后启用；此前不允许提前结束 |
| 暂停 | 暂停标题、已冻结模拟的说明、当前选中按钮 | 继续游戏、结束当天并结算、退出游戏；允许从这里提前结束当天 |
| 每日结算 | 当日完成订单、制作汉堡总数、手工/自动分项、提前/计时结束说明 | 进入下一天；第三天进入 Demo 完成页；未完成订单清除、无惩罚 |
| Demo 完成 | 三天各自的订单与制作统计 | 重新开始、退出；重新开始清空本轮动态状态并恢复初始布局 |

暂停/结算/完成使用全屏半透明遮罩和居中面板。建筑、传送带、收银和缓存选择本身不暂停生产；暂停及结算冻结模拟。手机“退出”具体含义、后台行为和额外确认弹窗尚未确定。

## 7. 绘制手机原型时如何整理信息

本节均为布局建议，不代表已实现或用户已经确认。

| 信息层级 | 建议内容 | 原型处理方式 |
| --- | --- | --- |
| 常驻核心 | 天数/倒计时、手持物、订单摘要、暂停与建造入口 | 保持简洁，为中间游戏场景留空间 |
| 情境信息 | 当前目标名称、获取/交换/放入/取出动作 | 靠近或选中后出现，配合情境交互按钮 |
| 设备详情 | 材料槽、加工进度、完成或等待原因 | 选中/靠近设备后显示，不把所有机器详情常驻堆叠 |
| 模式工具 | 放置、旋转、方向、取消、返回、精确调整 | 随建筑/传送带模式切换，不将所有模式按钮同时铺满 |
| 临时反馈 | 成功、失败、选择失效、损失明细 | 避开拇指和主要按钮；重要损失信息能看清 |
| 开发信息 | 版本、完整键盘说明、累计交接、手工状态测试文字 | 可考虑放入开发层或折叠；是否移除需用户确认 |

手机需要新增但目前未制作：虚拟摇杆、奔跑触控、情境交互与放下按钮、可见暂停/返回入口、镜头手势适配、旋转及精确调整触控、触屏引导等。横屏为建议，尚待填写确认。

明确区分三种数量：手持 1 件、缓存台 6 件、交付区 5 个汉堡。三者不能画成一个共享背包或库存数字。

## 9. 可交给 UI 原型工具的简要描述

> 设计一款手机端俯视角自动化汉堡店游戏的功能型 UI 原型。游戏有汉堡店和自动化车间，画面主体是可移动角色、原料点、工作台、自动设备、方向明确的实体传送带和六槽缓存台。保留天数与倒计时、订单进度、单件手持状态、当前交互目标与操作反馈。先表现正常游玩、建筑放置、传送带调整三种模式；手机触屏布局是设计提案，需明确移动、交互、镜头和施工拖动的区分。建筑菜单有自动烹饪台、自动汉堡组合台、十字拓展接口、直通隔离接口、转角隔离接口、缓存台六类。施工包含预览、合法/非法反馈、独立确认按钮、取消与返回；传送带先点建筑 A，再点 B，再调整方向和直角路径，放置后继续选 A。缓存选物在场景本体上完成，不制作新的库存弹窗。手持容量1、缓存容量6、交付区容量5相互独立。不要加入未有的金币、钻石、体力、商城、建筑价格、升级、技能、背包、顾客头像或自动交单系统。镜头保持垂直俯视和当前场景比例；风格、屏幕方向和具体触屏手势需用户确认。
